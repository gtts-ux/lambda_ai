# lambda 2.2

Published at the owner's explicit request even if quality expectations are not met.
This is not a claim that every reported error is fixed.

An experimental English conversation repair of lambda 2.1, trained only from the
owner's own weights. All Transformer layers, embeddings and the learned pointer
were updated on mixed multi-turn examples. Earlier trials froze most layers.
No external pretrained model, calculator, canned response, retrieval answer or
topic-based model switch generates chat answers.

- Parameters: 11,808,385; context: 512 tokens.
- Architecture: causal Transformer and learned pointer-generator, v4 format.
- Requires app **0.4.1**. The app fixes unintended float64 promotion in NumPy 2
  attention/GELU/pointer calculations; inference now remains float32 as in training.
- Continuation: 1400 updates from lambda 2.1, total step 24650.
- Training: 30,204 eligible examples from 30,270 newly generated synthetic examples
  (66 over the training length cap were excluded), with mixed histories, identity corrections,
  multiple people, missing facts, topic changes, arithmetic and copying, plus replay
  of earlier training examples. Sampling balances tasks; raw counts are not proportions.
- Origin: the owner's original random-initialized model and locally learned tokenizer.
  Training scripts, datasets, optimizer state and private checkpoints are not bundled.

## Measured comparison

Every preceding assistant message was generated by the evaluated model. No ideal
assistant history was supplied. Selection used 38 exposed development turns from
reported failure patterns; these are **not an independent test**.

Selected development result: 30/38, compared with 2/38 for 2.1.

The post-selection set was frozen before training finished and was not used to
choose a checkpoint. It contains new names/codes and changed conversation sequences,
but synthetic task templates overlap training. Exact normalized matching can reject
valid paraphrases. This small test does not measure broad intelligence.

| Decoding | lambda 2.1 | lambda 2.2 |
| --- | --- | --- |
| top-k 1, seed 2202 | 8/50 | 23/50 |
| top-k 8, seed 2217 | 7/50 | 20/50 |
| top-k 8, seed 2231 | 7/50 | 25/50 |

Temperature is 0.4, reply limit 80 tokens. The app defaults to top-k 8, temperature
0.4 and 120 tokens. The separate incident replay uses the full 120-token default.
See [raw benchmark answers](lambda-2.2-benchmark.json) and
[before/after incident conversations](lambda-2.2-conversations.json).

The initial target of 70% exact matches in every post-selection run was **not met**.

## Limits

This remains a very small experimental model. It can still miscopy unfamiliar
strings, confuse details and give incorrect arithmetic or explanations. Longer or
unfamiliar conversations can fail even when the short examples pass. The current
context is not permanent memory. This release is not a claim that all earlier
failures or the historical 1.6/2.5 release thresholds have been resolved.

For example, the recorded default-mode replay correctly recalled **Janek** and
**15**, but still answered **50** to `what is 5x6?` after a greeting and shortened
`Q7-xB2.` to `Q7-xB.`. The fresh greedy test changed **Talorin** to **Torin**.
These are remaining model errors, not claims of successful fixes.

The float32 correction removed the previously reproduced NumPy warning on the
recorded seven-turn replay. Final values and cached calculations were checked;
that result does not promise identical floating-point behavior on every platform.

Previous models and the shared 1,000,000-token / 10-hour allowance remain available.

## Install

Update the app from your checkout, then install the named model:

```bash
git pull --ff-only
.venv/bin/python -m pip install .
lambda update
lambda model use lambda-2.2
```

On Windows, replace the Python command with `.venv\Scripts\python -m pip install .`.
Restart an already open terminal app before selecting the new model. `/update`
updates model files/catalogs; it does not upgrade application code.
