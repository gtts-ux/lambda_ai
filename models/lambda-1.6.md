# lambda 1.6

An English model for short questions, elementary arithmetic and conversational
requests that contain numbers. It continues the owner's locally trained lambda
1.5; no external pretrained model, embedding service or text-generation API is used.

| Property | Value |
| --- | --- |
| Model ID | `lambda-1.6` |
| Total learned parameters | **2,614,528 — exactly 3.5× lambda 1.0 (747,008)** |
| Generator / intent head | 2,613,190 / 1,338 parameters |
| Architecture | Autoregressive MLP, two tanh layers, learned mode bias and intent head |
| Rolling generation context | 80 tokens |
| Question features | Last 64 question tokens, fixed hashed features in chat mode |
| Embedding / hidden layers | 24 / 640 → 640 |
| Vocabulary | 1,462 locally learned BPE tokens; individual digits |
| Precision / device | float32 / local CPU |
| Selected 1.6 checkpoint step | 25,000 |
| Inference file | 9.27 MiB |
| Minimum app version | 0.2.0 |

## Install and select

Upgrade the application in an existing checkout first:

```bash
git pull
bash install.sh
lambda
```

Then use `/update` and `/model use lambda-1.6`. `/intent Explain Python 3`
shows the learned routing decision. The CLI equivalent is
`lambda intent "Explain Python 3" --json`.
Models 1.0 and 1.5 remain selectable. Switching preserves the shared token allowance.

## Training and inference

The owner's lambda 1.5 checkpoint at step 37,500 was expanded from hidden width
560 to 640, its context extended from 64 to 80, and its own tokenizer continued
from 1,184 to 1,462 tokens. Duplicated hidden units initially share the original
function; new earlier context rows and mode biases start at zero. The new
generator and a separately initialized intent head were trained locally with
NumPy and manually implemented gradients. The inference metadata records lineage
and source checksums.

The final curriculum has 12,001 English training questions and
15,027 arithmetic training questions, with 1,308 English and 698
arithmetic validation questions. English examples include original definitions,
greetings, clarifications, short instructions, and varied phrasings with unrelated
numbers. Arithmetic retains lambda 1.5's operand-family split; new wording is
generated only for training families. The intent head learns from these labelled
questions, using 668 signed hashed word and character features
and two softmax outputs. Its validation-selected math threshold is 0.75.

The generator receives a learned bias for the predicted mode. In chat mode,
768 fixed hashed features of the bounded question are also added to its embedding
input and processed by the existing learned first-layer weights. This helps with
changed word order without introducing extra learned parameters. The question
features persist only while generating that answer. They are derived from input
already covered by the prompt's token charge, not earlier conversation turns.

All answer text is generated by the neural network. There is no arithmetic
evaluator, answer lookup, retrieval database or correction step at inference.
The exported model contains inference weights, feature configuration and its
tokenizer; it contains no training examples, optimizer or training loop.

## Measurements

The initial 40-case development set exposed weak paraphrase handling and informed
additional training variants. A separate 40-case set was then frozen before
inspecting predictions from the expanded training. Its exact questions have no
overlap with the checked training data. Topics and answer facts are familiar;
this measures new wording, not unseen knowledge. Checkpoints are selected by
validation loss rather than either evaluation set.

| Intent routing, lambda 1.6 | Correct / total |
| --- | --- |
| Development set | 40/40 (100.0%) |
| Additional held-out wording | 39/40 (97.5%) |

Routing accuracy measures chat versus calculation intent, not answer correctness.
Lambda 1.5 has no explicit intent head.

| Incorrectly number-only answers on held-out chat questions | lambda 1.5 | lambda 1.6 |
| --- | --- | --- |
| Chat without digits | 1/15 | 0/15 |
| Chat containing digits | 2/15 | 2/15 |

Avoiding a number-only reply does not establish that an answer is coherent or true.
The raw report also records a narrow topic-keyword proxy, which is not a semantic
correctness score and can reject valid short replies or accept wrong ones.

The same 142 arithmetic questions used for the 1.5 comparison were retained:

| Arithmetic exact answers | lambda 1.5 | lambda 1.6 |
| --- | --- | --- |
| Familiar operands, new wording | 64/96 (66.7%) | 75/96 (78.1%) |
| Held-out operand families, new wording | 16/46 (34.8%) | 17/46 (37.0%) |

Sampling uses temperature 0.4, top-k 8 and seed 7; the output cap is 100 tokens for
conversation/intent cases and 48 for the arithmetic benchmark. Outputs are not
rewritten. All questions, labels, targets and unedited answers from both models
are in [lambda-1.6-benchmark.json](lambda-1.6-benchmark.json). Its model checksum
matches [lambda-1.6.json](lambda-1.6.json).

## Limitations

This remains a small educational model. It can misclassify requests, produce
unrelated or broken English, and give incorrect arithmetic results, including
within familiar ranges. A routing probability does not measure answer quality.
Training on more variants does not establish broad language understanding.

It has no conversation memory, live internet information or tool execution.
The 80-token context and bounded question features are separate from the shared
1,000,000-token allowance, which resets after 10 hours. Check important answers
independently. Code and these inference weights use the repository's MIT license.
